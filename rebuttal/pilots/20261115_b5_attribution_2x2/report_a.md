# Attribution 2x2 (design A): judge swap vs fixed-fact labelling swap

2026-11-15. Rule `B5-attribution-2x2-amendment-1.md` (sha `a8ee8a0b...`), parent `B5-attribution-2x2.md` (sha `0441ed1c...`), frozen before any call. Population: the 89 known-stage cases (30 injected, known transmission; 59 cohort, 39 extraction / 20 sharding). 2x2 spend $0.862423 (cap $4.00).

## Design, plainly

- **Judge row:** the whole judge is swapped. Same frozen `attribution_prompt_v1.json`, same case text, model Qwen-235B vs Gemini 3.6 Flash. The model regenerates everything from the trace.
- **Audit row:** only the labelling model is swapped. The facts are the Qwen matcher's own, frozen; the carrier-labelling call (`CARRIER_PROMPT`, frozen) runs with Qwen or Gemini on the same facts and the same checkpoints; the same `diagnose_with_sharding` produces the stage.
- The earlier Gemini-regenerates-its-own-facts audit failed validation (.316 agreement) and is not part of this design; it stays on record as the failed attempt.
- Both rows answer whether the method or the model does the work: in the judge row the model writes the facts and the verdict; in the audit row only the carrier labels change.

## Caveat on the audit row

The audit row's facts are the frozen Qwen matcher's own facts, and the carrier step then labels them. That fact set was generated by Qwen-235B, so the audit row may favour Qwen labelling: the Qwen advantage there (+.101) is confounded with who wrote the facts, and it cannot be read as Qwen being the better labeller in general. The Gemini-regenerates-its-own-facts design, which would remove this confound, is the design that failed validation (.316 agreement) and is not reported as a result.
