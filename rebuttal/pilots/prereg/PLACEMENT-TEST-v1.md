# Placement test v1 — new pre-registration, own action manifest

Date: 2026-11-13. New file. This is not E4-P and does not amend E4-P, E4-v7,
A1, A2 or A3. Pilot only; no full run and no paper edit.

## Question

Does it matter **where** one corrective evidence unit is placed on the board —
attributed to the agent whose shard it comes from, or to a different agent —
when the text is identical and the volume is identical? E4-P calls the first
placement `target` and the second `hash`.

## Population

The 78 seed-43 traces under
`rebuttal/results/batch1/E4P_seed43/{qwen,gpt,gemma}/traces/*.json`
(26 Silo-Bench n=10 tasks x 3 base models; k=1). Every trace is named in the
action manifest with its trace hash, instance id, model, gold answer, board
hash, target agent, hash agent and inserted text. The manifest is hashed
before any placement call.

## Labeller step

All 78 traces are labelled with the frozen evidence-flow labeller v2
(Claude Haiku 5.5, temperature 0). Ten labels are spot-checked by hand (four
correct and six wrong answers, at least three model families) against the
rendered trace, and agreement is reported. The labeller is used for screening
only: answer correctness is the frozen exact rule below.

## Placement rule (fixed before outcomes)

- **Target agent.** For each trace, the agent with the highest `composite`
  score among its pool units in the frozen `scores` array; ties by lower
  `agent_id`. If `scores` is missing, agent 0, flagged `target_fallback`.
- **Hash agent.** Among the other agents, the one with the smallest
  `sha256("43|" + trace_id + "|" + agent_id)`. Never equal to the target.
- **Inserted text.** The first line of the target agent's `source_supports`
  entry that matches one of `Agent {target} holds`, `You (Agent {target})
  hold`, `The agent at position {target} holds`, or the line immediately
  after a `**Your Data (Position {target})...**` header; if none, the full
  support text truncated to 400 characters, flagged `text_fallback`. The same
  text is used in both arms.
- **Arms.** `target`: the text added as one new board unit with
  `agent_id = target` (unit id `P-t:<target>`). `hash`: the same text added
  with `agent_id = hash` (unit id `P-h:<hash>`). Board size increases by one
  in both arms; no other field changes.
- **Aggregation.** `_AGGREGATION_SYSTEM` and `_build_evidence_board_prompt`
  with the units grouped by `agent_id`, the trace's own model, temperature 0,
  seed 43, max output 1024.
- **Scoring.** `silobench_exact_match(extract_answer(answer_text),
  {"answer": gold_answer})`, the same comparator that produced the stored
  `answer_matches_gold`.

## Pilot

Six traces, two per model family, chosen from the traces the labeller labels
`DEFECT` and whose stored answer is wrong, by ascending
`sha256("43|pilot|" + trace_id)`. Twelve aggregation calls (6 x 2). Cap **$5**,
one attempt per arm, every call logged with intent and result. A trace whose
two arms have different inserted text is reported and not scored; the text is
identical by construction, so this is a check, not a repair.

## Endpoints

- labeller DEFECT rate over the 78, with exact 95% CI;
- spot-check agreement (n=10), disagreements listed;
- per-arm exact counts and the paired target-minus-hash difference, reported
  descriptively at n=6 (counts, not a population claim);
- cost. No cluster-bootstrap claim at this size.

## Guardrails

No injection is generated; the inserted text is a verbatim line from the
trace's own source supports. No human labels are generated by a model. No
result is written by the labeller. No full run, no paper edit, no commit.
